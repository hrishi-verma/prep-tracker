How it works

One pattern a day: 5 required, 5 optional. Click Solved when you solve one. The pattern moves on once all 5 required are solved.

Everything you attempt joins the revision list the next day. Solve it again and press +1. 🌱 🌿 🪴 daily for 5 revisions, then 🌳 weekly. Once weekly, Know it cold retires it as ⭐ Perfected.

Skip a due revision 2 days running and it slips: it goes to the top of the list and starts the climb again.

Questions done before the switch count as Solved and join revision after their first +1.

What this is

A personal LeetCode practice tracker for Hrishikesh (Rishi) Verma. One HTML file, no server, no framework, no build step. It was written in September 2026 in a conversation with Claude and reworked in October 2026. Rishi owns it. It exists so Rishi can work through a fixed list of LeetCode questions pattern by pattern while preparing for software engineering interviews.

Why it was made

Rishi had already solved about 400 LeetCode problems. The remaining gap was not volume, it was pattern fluency: seeing a new problem and knowing which technique it belongs to, then coding it cleanly. So the tracker is built around patterns. The list is 35 pattern blocks of 10 questions (5 required, 5 optional) plus a mixed block of 40 where the pattern is hidden: 390 questions, none of them in Rishi's solved list at the time they were added.

The method the tracker enforces

  • One pattern a day. Today shows the pattern name, its 5 required questions and its 5 optional ones. The pattern stays until all 5 required questions have a status, so a missed day never skips a pattern.
  • Required questions 1 to 3 are for studying the solution and building a template, 4 and 5 are attempted cold. Questions 6 to 10 are optional extra practice.
  • The mixed block comes last, 5 required a day. For each one Rishi types his pattern guess before revealing the real one.
  • GregMat-style revision: every question attempted shows up in "Revise today" from the next day on. Rishi solves it again and presses +1. A question is revised daily until its climb reaches 5, then weekly. Only a weekly question can be retired with "Know it cold" (shown as Perfected; "Bring back" undoes it). If a due revision is skipped for 2 days running, the question slips and its climb restarts at 0; the total count is kept. Pressing +1 on a slipped question marks it Solved again. Plant icons show the stage: seedling, herb, potted plant (daily), tree (weekly), star (perfected).

Status and revision counter

  • Each question is either Solved or not. There is one Solved button (click again to undo); no Unsolved button and no dropdown. This was Rishi's explicit choice: keep it binary.
  • Each solved question has a revision counter starting at 0. +1 records one revision today and drops it from today's list; the minus undoes a mistaken click.
  • A question that slipped (missed revision) is stored with status "unsolved" so it stays in revision; it is shown as "slipped" in red and listed first. It still counts as done for moving to the next pattern.

Before October 2026 there were three labels (Solved, Revisit, Coding issue) and a 2/7/21 day retry cycle. Both were removed. Any old label now reads as Solved. Questions attempted before the switch are listed in v2.legacy and only join daily revision after their first +1, because Rishi had forgotten them. Do not bring the Learned label or the retry cycle back.

  • Header: the app is titled Prep Tracker; LeetCode, System Design and AI Fluency each open with three summary tiles in the same style.
  • Progress: overall percentage, revision totals, streak, activity heatmap (new plus revised), daily log, per-pattern bars.
  • System Design: a separate tracker with its own storage key sd-tracker-v1. Three tracks (collapsible, with a progress bar each) with a status dropdown per item, summary tiles and an Up next bar on top (the Telusko one-shot video in 10 units, Alex Xu Vol 1 in 16 chapters, Alex Xu Vol 2 in 13 chapters), and a free-text log: Rishi writes what he did, presses Log, and the entry becomes a dated card on a timeline. Nothing in the log is pre-written; gaps between days are shown as gaps. The log is deliberately free text with no tagging.
  • AI Fluency: built from Rishi's research doc on a free learning path to SWE, ML and AI engineer roles (October 2026). Where the data lives and how to keep it safe

Progress is not stored in this file. It is stored in the browser's localStorage under three keys: lc-tracker-v1 for LeetCode, sd-tracker-v1 for System Design and ai-tracker-v1 for AI Fluency. Export and Import handle all three together. Replacing the HTML file with a newer version keeps all progress as long as that key and the data shape survive. Rules for anyone editing this file:

  • Never rename the storage key.
  • Never rename or delete a field inside the saved object. Add new fields instead.
  • If a change in data shape is unavoidable, add a conversion step inside the migrate() function that runs on load, so old data is transformed rather than lost.
  • Keep Export and Import working. They are the user's safety net.
  • Question ids are the keys for all saved data. Adding questions is safe; changing an existing id is not.

Saved fields. Current: st (question id to status, first attempt date f and last change date), rc (question id to revision count n, dates h, last, climb k, next due, undo stack u, last lapse lap, retired date ret), lapsedOn (date the daily lapse check last ran), rlog (date to revisions that day), log (date to questions first attempted that day), day (today's pattern and question ids), v2 (switch date and legacy ids), notes, guess, gs (Goldman question key to date ticked). Old and kept untouched: labels (read as Solved when no st entry), sched, rv.

How the code is laid out

Everything is in one script block at the bottom of the file. PATTERNS holds the question list as pattern name plus an array of [id, title, difficulty, optional hidden pattern hint]; in each normal pattern the first 5 are required and the next 5 optional. st() reads status, setStatus() writes it. ensureToday() picks the day's pattern. revUp(), revDown(), lapse(), retire(), inPool() and revDue() run revision. render() redraws everything from state after each change. LeetCode links are generated from the title by slugifying it.

Design intent

Colorful and friendly, one page, quick to act on. Each pattern has its own hue so tiles are recognisable at a glance. Solved is green, slipped red, revision purple, used consistently everywhere. Keep the page compact. Rishi prefers short text and dislikes being overwhelmed, so avoid adding walls of explanation to the interface itself.

Things to keep in mind when changing it

  • Do not use em dashes anywhere in the text.
  • Keep it a single HTML file with no external dependencies other than the Google Font, which has a system fallback.
  • Do not add browser storage other than the three existing localStorage keys.
  • Any new feature should serve pattern fluency or honest self-assessment. Cosmetic additions are low priority.
